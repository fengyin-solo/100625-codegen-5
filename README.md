# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 起重设备定期检验台账（`crane`）

针对坝顶门机、尾水门机的“谁来检、到期谁盯”问题，在通用台账之外单独建的**带归属的检验域**。
数据独立存放在 `localStorage` 的 `hydropower-plant-om:crane-lifting:v1`，账号选择存
`hydropower-plant-om:crane-account`。代码：

- 领域类型 / 现行版别限值 / 种子数据：`frontend/src/data/crane/`（`types.ts`、`constants.ts`、`domain.ts`、`store.ts`）
- 服务层（鉴权、结论录入、去重、迁移、导出、跨模块桥接）：`frontend/src/api/crane-service.ts`
- 页面：`frontend/src/views/crane/index.vue`；闸门/水情入口的联动待办组件：`frontend/src/views/crane/CrossModuleTodos.vue`
- 端到端检查：`npm run test:crane`（34 项：权限四档、去重、实测优先、预警收回、迁移断点续走、跨模块待办、报表一致）

### 归属与权限（服务层强制，页面只读/隐藏只是表现）

- 每台设备必须登记**使用单位**与**检验机构**，外加唯一的闸门启闭对象编号（操作工从另一入口认得出来）。
- 检验结论只有「检验机构 + 持有效起重机械定期检验资质 + 机构与设备登记归属一致 +
  使用单位在该机构授权范围内」的账号能录入。
- 使用单位账号：只许看、不许动结论；外来账号（集团审计）：全部只读。
- 跨机构替别人录、机构对但跨单位（授权范围不含该使用单位）、资质失效：越权提交一律挡回，
  页面顶部与「权限日志」页给出逐档理由。页面上另有「模拟越权提交验证」按钮直接验证拦截。

### 到期、停用与跨模块回写

- 默认提前 **30 天**发到期预警（每台设备可改提前量）；超期未检自动挂停用牌；
  末次结论不合格立即停用。
- 检验结论不只挂在设备台账：按设备同步生成/解除**闸门启闭**与**水情调度**两个入口的联动待办；
  门机还以桥接行同步到闸门启闭列表，操作工对停用门机点「开启闸门」会被硬拦截并说明理由。
- 到期预警发出后完成定检：预警**收回**（状态变「已收回」、记录保留并写明收回报告号），
  两个入口待办随之解除；历史检验结论只追加、永不覆盖。

### 报告、去重与取值规则

- 同一份检验报告重复上传只留一条：**按报告编号全局去重**（存量迁移同样适用，
  早年纸质报告统一用 `PAPER-原报告号`）。
- **实测值优先**：钢丝绳直径磨损率、制动器开式瓦块间隙给了实测值，就按现行限值
  （磨损率 7%、间隙 1.0mm）统一取值判定；手填主观结论与实测冲突时以实测为准并提示。
- 现行版别：`TSG Q7015-2016 起重机械定期检验规则`，定检周期缺省 24 个月。
- 早年只有纸质报告的：建电子档并标「纸质归档、原件存档案柜待核」；无磨损实测的缺项
  按现行版别推断为合格取值并打「缺项推断」标记，不伪造数字。
- 存量设备按**投运年份**回填；历史报告按**检验发生日期**补数。无任何报告的设备只建档、
  不补结论，挂停用牌等待首检。

### 存量迁移顺序（页面「存量回填迁移」页可逐步/一键执行）

1. 基础主体：使用单位、检验机构、账号与资质（内置）；
2. 设备回填：按投运年份升序逐台建档（游标 `deviceCursor` 持久化）；
3. 报告补录：按检验发生日期升序逐份归档，报告编号去重、实测值优先、缺项推断打标；
4. 全量到期扫描：重算状态、预警、停用牌与两个入口待办；
5. 汇总：数字全部从明细实时统计，台账卡片与导出 CSV 同口径。

取数中断（如外委单位的磨损记录没交齐）时迁移**在断掉的那一条停住**，游标不前进，
绝不拿旧值顶替；在「续取」补齐实测后从该条接着走。想重跑：页面「恢复演示基线」
或清掉 `hydropower-plant-om:crane-lifting:v1`。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。
